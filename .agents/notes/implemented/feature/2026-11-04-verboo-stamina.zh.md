# Agent Note: Verboo 耐力展示

Status: implemented

[English](2026-11-04-verboo-stamina.md) | 中文

## 问题

选定的无限订阅用户需要了解新请求的速度，但不应看到内部预算。桌面应用无法从实际生成速度推断网关的准入上限，而且账号切换时旧 HTTP 读取可能仍未完成。

## 决策

产品 API 读取经过身份验证的服务器公开耐力数据。网关负责启用范围、用量和限速。Client 不添加准入策略，也不展示金额储备。

输入框和“我的订阅”使用同一个注册资源。资源地址包含当前凭据版本和个人资料 ID；账号替换会取消旧读取并拒绝迟到响应。可见且在线的使用方一次只驱动一个有时限的读取。失败会保留上次确认的数据并显示本地化提示，服务器返回空列表则隐藏耐力。缺少端点时同样返回空列表，以兼容旧部署。

## 考虑过的替代方案

**从实际 TPS 推断上限。** 提供方容量和传输延迟会独立于服务器预算影响实际速度，因此该读数无法确定准入上限。

**由每个组件独立轮询。** 独立缓存可能不一致，并保留不同账号版本的数据。现有资源注册表提供共享数据，并在最后一个使用方离开时释放提供方。

## 影响

耐力不进入提示词、Session 持久化或本地凭据。离线窗口显示保留的读数，而不会虚构恢复。此功能仍要求后端试点选定相应账号和订阅。

所属 API、资源生命周期和组件测试覆盖无效响应、失败、账号变化重放、取消和本地化读数。构建后的浏览器验收使用本地 API 覆盖已注册视图。
