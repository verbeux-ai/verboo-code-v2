# Agent Note: 原生试用提醒与明确的订阅转换

Status: implemented

[English](2026-11-17-native-trial-conversion.md) | 中文

## Problem

桌面客户端的简短订阅投影无法说明试用余额耗尽，也无法提供可信的付款决定。仅在仪表板显示提醒，会让聊天中的买家缺少明确的下一步。依据推理错误或独立客户端时钟推断试用结束，还会混淆服务故障与商业状态。

## Decision

后端投影试用提醒、剩余令牌和已付款分组权限。应用在到期前24小时或剩余20%令牌时显示输入框提醒，以先发生者为准。试用实际结束后打开可关闭的报价，突出 Pro，同时展示其他套餐。关闭只对当前窗口有效，因此再次启动应用后会重新显示已结束的试用。提醒上下文来自当前聚焦窗格已接受模型对应的服务器分组。

产品 Host 保存签名授权。客户端接收金额、周期、有效期和脱敏银行卡摘要，不接收支付服务商的客户或付款方式标识符。查看报价、银行卡设置、试用套餐转移及扣款保持独立。每次扣款需要展示中的报价及明确授权；变更或过期的报价需要再次确认。订阅周期在已持久化的付款确认后开始。

套餐目录仍以 USD 计价。巴西主账号的 Pix 购买从后端官方汇率缓存取得独立签名的 BRL 报价，固定 BRL 续费金额，并显示包含 IOF 的银行授权上限。原付款尝试保存 USD 和汇率证据。浏览器跳转或成功返回链接不能证明付款。重启、超时及额外认证都恢复原付款尝试。

## Alternatives considered

**仅在仪表板提醒。** 产品要求在应用内、试用影响聊天使用的位置提供操作。

**展示报价或保存银行卡后自动扣款。** 两者都不构成此流程要求的明确授权。银行卡设置完成后需要再次审核报价。

**客户端自行换汇。** 无法将展示金额绑定至服务器收费，也无法在汇率变化后安全保留原尝试。Pix 使用独立签名的服务器报价。

**无限期保存关闭状态。** 会在重启后隐藏升级机会。每次轮询重新打开又会打断导航，因此关闭仅持续当前窗口。

## Consequences

后端及汇率快照 migration 必须先于客户端发布。不受支持的付款方式保持不可用，不进行近似转换。支付服务商仅支持浏览器的步骤仍在外部完成，直到存在原生支付流程。商业数据和全部新增 Remote 操作在共享会话中仅供拥有者使用，不进入模型上下文。

所有权、报价、展示及恢复测试位于各所属包中。Loader 组合测试使用外部 HTTP fixture，验证查看 Pix 报价不会创建购买，重复确认仅创建一次结账。当前 Agent Note 树中没有需要取代的早期 Verboo 试用转换决定。
