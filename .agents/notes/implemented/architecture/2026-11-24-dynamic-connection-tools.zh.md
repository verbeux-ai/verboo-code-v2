# Agent Note: Dynamic connection tools from a capability search

Status: implemented

[English](2026-11-24-dynamic-connection-tools.md) | 中文

## Problem

像 Gmail 这样的已连接服务会暴露数百个提供方动作，其参数 schema 会随提供方每次发布而变化。提前声明全部动作会把请求预算花在对话从不调用的定义上，而为每个提供方动作手写一个工具也跟不上目录的变化。

先前的做法把一个通用 `connections_execute` 工具当作挡板，它接收 `connectionId`、`slug`、`version` 和一个自由格式的 `arguments` 对象。模型可以运行动作，却永远看不到该动作的真实 schema，只能猜测字段名并从拒绝结果中学习。没有任何东西把已发现的定义与使用它的调用绑定起来，模型也可以把任意账号传给任意 slug。

## Decision

`connections_search` 是发现步骤。它读取账号的连接，向提供方查询匹配某项能力的工具，并把每个匹配项以 `connection__<toolkit>__<slug>` 注册到调用方 Agent 自己的工具注册表中。随后模型在下一步、同一个请求内直接调用该工具。

注册是 Agent 作用域内普通的 `ctx.tools.register()` 贡献。因此下一次提示词装配会声明新工具，循环会把这次新增记录为 `tool-registry` 的 developer 消息，模型看到的是真实名称、描述与参数 schema，而不是不透明的执行调用。释放随 Agent 作用域进行，因此后续对话只从基础工具开始。

提供方 schema 在注册前会投影到受支持的工具 schema 子集。不受支持的关键字、格式错误的节点，以及属性映射未声明的 `required` 键都会被丢弃而不是转发，因为转发会让上游提供方改变 harness 校验参数的方式。超过 `discoveryMaxSchemaBytes` 的投影会保留开放式参数 schema：工具仍然可调用，模型从提供方自己的拒绝结果中了解字段，这仍然好过丢弃该动作。

每个已注册的工具都闭包持有它自己那次搜索解析出的连接与版本，因此后续搜索无法把先前的调用重定向到别的账号。已经在服务其他账号的名称绝不会被复用：第二个账号的副本会获得哈希后缀。对同一账号和 slug 以更新的提供方版本重复搜索时，会替换注册而不是复制它。

账号选择始终显式。拥有多个已连接账号的工具包会被报告为歧义并带上账号标签，Agent 在使用该 `connectionId` 重新搜索前先询问使用者选哪一个。默认搜索所有服务是有意为之：使用者的请求很少点名工具包，能力查询比猜测是更好的过滤条件。

一段提示词章节会说明存在已连接的服务，并说明 `connections_search` 是到达它们的途径，因为模型从未考虑过的工具与不存在的工具无法区分。

## Alternatives considered

**保留一个通用执行工具并增加一个独立的描述工具。** 在开始工作前要两次往返，而且模型仍必须把 slug、版本和连接复制到第二次调用中，而这正是导致错误账号调用的配对方式。

**提前声明每个提供方动作。** 目录很大，大多数动作与对话无关，而请求从不调用的定义仍然要在每一步消耗声明 token。

**把已发现的工具注册为全局而不是按 Agent 注册。** 全局注册会把一次对话的发现泄漏到其他所有对话，并使释放含义不清；Agent 作用域本身已经拥有按对话的工具。

**原样转发提供方 schema。** harness 只强制其文档化的子集。转发它忽略的关键字会呈现一个从未被检查的约束，而位于 `properties` 之外的 `required` 键会让每次调用都校验失败。

**让模型通过选择第一个匹配项隐式决定账号。** 在同一服务的两个个人与工作账号之间静默选择，有操作错误邮箱的风险。

## Consequences

集成任务现在在动作前需要一个搜索步骤，且已发现的声明会留在对话中，因此长会话会累积它实际使用过的工具，而不是一个固定目录。`connections_execute` 已移除；该工具名从产品界面消失，调用过它的已存会话在重放时会表现为未知工具。

超过 schema 字节预算的提供方动作可调用但未被声明，这是用首次调用的拒绝换取大定义在每一步会消耗的 token。发现是按对话的：在新对话中继续的工作会重新搜索。

覆盖位于包内。`discovery.spec.ts` 固定 schema 投影、命名、歧义、账号隔离、版本替换、预算边界与释放；`discovery-loop.spec.ts` 驱动真实 Agent 先搜索，然后在同一轮中调用两个已发现的工具，并断言第二个请求声明了它们；`tool-wiring.spec.ts` 断言基础界面以及被移除执行工具的不存在。
