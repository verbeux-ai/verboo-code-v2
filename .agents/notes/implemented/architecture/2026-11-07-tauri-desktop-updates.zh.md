# Agent Note: Desktop updates from a branch-hosted feed

Status: implemented

[English](2026-11-07-tauri-desktop-updates.md) | 中文

## Problem

[Tauri 载体](2026-11-04-tauri-desktop-carrier.zh.md) 从 GitHub Releases 安装，而每次发布都不带更新器：应用不读取更新源，也无法替换自身。因此新版本只能到达那些主动找到发布页并重装的用户，而此前的发布说明不得不解释“重启应用不会有任何变化”。

[Electron 打包决策](2026-08-25-electron-desktop-packaging-and-updates.zh.md) 描述过更新器，但它属于旧载体及其服务；Tauri 应用既不连接前者也不连接后者。

## Decision

应用使用 Tauri 更新器插件自行更新，更新源提交在 `update-feed` 分支上。

### 三种平台机制，一条流程

该插件要求签名且无法关闭，因此打包器通过 `createUpdaterArtifacts` 输出更新包，并用 `TAURI_SIGNING_PRIVATE_KEY` 为其签名。`plugins.updater.pubkey` 中的公钥内嵌在应用里，是唯一的信任锚：由其他密钥签名的更新会被拒绝。私钥一旦丢失，所有已安装的应用都将永久退出后续更新，因此它是发布凭据，而不是构建上的便利选项。

更新器替换的对象因平台而异，更新源指向的产物也随之不同。Linux 和 Windows 复用安装器自身的字节，因为 AppImage 和 NSIS 安装器会直接替换已安装的文件；Windows 以 `passive` 模式安装，只显示进度而不再询问。macOS 无法用磁盘映像替换正在运行的应用，因此打包器归档 `.app`，更新源指向该归档。Debian 与 RPM 安装被排除在外：这些文件归包管理器所有，更新也由它负责。

### 原生提示，而非客户端界面

Host 开始提供产品页面之后，Rust 每次启动检查一次更新源，并用应用已经组合的 dialog 插件询问。若由客户端代码检查，就要为原生层本就掌握的决定新增一项权限和一个界面接口，而且窗口在此期间的就绪报告会变得不一致。开发构建从不检查，因此检出目录不会自行安装发布版本覆盖自身源码。

被拒绝的版本记录在应用配置旁边，同一更新只询问一次，而不是每次启动都询问；更新的版本会再次询问。其余结果一律保持静默：更新源不可达、清单格式错误或安装被拒绝都不能阻塞启动或显式失败，因为应用在其他方面仍可使用。

### 更新源放在分支上

显而易见的端点 `releases/latest/download/latest.json` 在这里永远无法解析：`latest` 选择的是最近的非预发布版本，而 Verboo 的每次发布都是预发布版本。因此把更新源作为发布附件发布，恰恰会在最需要它的时候无法访问。

更新源改为提交到 `update-feed`，它对任何版本都能解析，且不改动已发布的安装器字节。`verify-release.mjs` 依据校验过的各平台清单推导出它，因此更新源中的 URL、大小和签名描述的正是该次发布所发布的字节；`publish-feed.mjs` 在发布公开后提交它。重跑旧版本的发布不会让更新源倒退，相同版本会被拒绝而不是重写。

## Alternatives considered

**把更新源作为发布附件。** 对预发布版本不可达，且已安装的应用没有认证过的备用路径。

**把更新源放在下载服务上。** 对生产渠道而言是正确的，但[发布参考](../../../../apps/desktop/publishing/README.zh.md)把该服务保留给经操作者授权的、带 COS 凭据的发布，而仅依赖 GitHub 的 alpha 渠道并不具备其中任何一项。

**由客户端检查更新。** 需要新增客户端权限和原生命令，并重复一项其结论会驱动原生对话框与应用重启的检查。

**先发布经过公证的 macOS 构建。** 公证需要 Apple Developer 身份，而更新器独立于 Gatekeeper 校验自身签名。临时签名让 alpha 渠道继续可用；公证构建是对本决定的补充，而不是前提。

## Consequences

从下一个已发布版本开始，alpha 安装能够自行更新；首个带该插件的版本无法由不带该插件的版本安装，因此过渡只需一次手动安装。临时签名的 macOS 构建在更新后仍可能被 Gatekeeper 隔离，Developer ID 与公证可以消除这一点。Windows 安装器仍未签名，可能触发警告。更新源分支是发布记录：手工编辑它等于向所有安装发布一个版本，因此它始终由工作流拥有。
