# Agent Note: Deleting a stored Session

Status: implemented

[English](2026-11-09-session-deletion.md) | 中文

## Problem

归档曾是收拾一段对话的唯一方式，而它刻意保留一切：归档集合隐藏行，转录仍留在磁盘上，工作区账目保留其槽位，取消归档即可恢复位置。想要一段对话彻底消失的用户——它可能带着写错的提示、泄露的凭据，或只是一次不再想被列出的试验——既没有产品动作，也没有接缝操作：`SessionPersistence` 只提供 create、open、stat、list、flush 以及句柄，组合中没有任何东西能删除日志。唯一的手段是在存储根下手动删除文件，而这只会在反方向留下孤儿注册表账目：介质已不再持有的 id 仍留在归档集合与某个工作区账目中，直到重启重新建立索引。

删除也不能是纯存储操作，因为会话可能正处于回合中。在运行中的回合底下移除日志，会让该回合向刚被删除的路径追加，从而静默地重新实体化用户要求销毁的会话，并让仍在运行的子代理、后台任务与提醒无处写入。

## Decision

删除是一条新的能力接缝路径，而不是归档的变体，并由已经拥有该事实两半的两个包各自拥有。

**存储契约新增一个破坏性方法。** `SessionPersistence.remove(id)` 删除后端为该会话拥有的全部产物，并在它们消失后完成。它定义在 Service Definition 上，带一个具体的默认实现，以 `SessionRemoveUnsupportedError` 拒绝，而不是声明为抽象成员：不保留可移除的每会话产物的后端必须显式拒绝，绝不报告一次它做不到的删除；同时，那些继承该服务的已发布测试替身无需假装拥有它们并不具备的能力即可继续编译。`SessionPersistenceRemoveOptions` 携带在后端工作开始前观察的取消。

**JSONL 后端只按 id 寻址删除。** `remove` 删除每个项目目录下的 `<project>/<encoded-id>/`——该目录拥有全部不可变世代与全部附带产物——随后删除已退役布局写在其旁的扁平文件拼写。它从不删除共享的项目目录，也从不先读头部：头部损坏或高于本构建版本的日志必须仍然可删，根目录的编码检查也不得阻止用户要求的删除。id 就是地址，因此没有产物的 id 不写任何东西即完成（重复或竞争即空操作）；文件系统拒绝时报错，并让会话保持原样可见，因此调用可以安全重试。由于进程内状态否则会为已不存在的产物作答，删除还会丢弃该 id 的交接解析缓存、中止其进行中的迁移准备，并丢弃其已创建但未实体化的条目。

**注册表拥有顺序、账目与运行中工作的规则。** `WorkspaceRegistry.deleteSession(sessionId, { stopActivity })` 复用两个归档准入事件并把顺序反过来。没有 `stopActivity` 时它只询问一次 `workspace/session-activity`，对非空答案在任何写入或删除之前以 `WorkspaceActiveSessionError` 拒绝——与归档同一类型，消息中现在带上 `delete` 动词。带 `stopActivity` 时它先询问 `workspace/session-stop`，之后才移除转录，因此不会有回合向即将消失的日志追加；拒绝的提供方只记日志，而不是保住用户要求销毁的转录。移除成功后，它删除头索引条目、将该 id 从归档集合与置顶集合中移除、从每个工作区账目中剪除，然后重新发布实体快照。

**失败绝不留下静默孤儿。** 后端移除失败在任何账目写入之前传播，因此行保持可见，调用可以安全重试。移除**之后**的失败以 `AggregateError` 拒绝并说明删除已提交；内存投影此时已丢弃该会话，因此没有任何面会继续显示日志已不存在的行，且启动重新索引会清掉悬空 id。API 把该状态映射为自己的 Remote 码 `workspace/delete-incomplete`，使面可以说明对话已消失、只剩清理在等待，而不是报告一个泛化失败。

**未知 id 已处于请求的状态。** `deleteSession` 对注册表不认识的 id 正常完成，因为请求的终态就是"不存在"：重复点击、与其他面竞争失败，或陈旧行都不该失败。这与 `archiveSession` 不同：归档拒绝未知 id，因为向集合添加元素并不在同一方向上幂等。

**动作需确认，且只有对话框调用 Host。** `ui-workspace` 为 `session` 目标在 order 700 贡献一个 `ctx.contextMenus` 动作，标记 `danger: true`（共享 `Menu` 原语据此渲染为错误色文本与图标），并使用既有的 `trash-outline` 字形；它只抛出 `SessionDeleteConfirmRequest`，自己从不调用 Host。`shell.overlay` 对话框点明对话标题，说明转录将被删除、工作会先停止，且无法撤销。确认会调用 `deleteSession(id, { stopActivity: true })`；取消则结算请求，什么都不删除。`UiWorkspaceService.deleteSession` 在该会话正是当前选中项时清除选中，随后刷新会话列表，使行经 Host 列表消失，而不是作为日志已不存在的行残留在界面上。

## Alternatives considered

**用归档上的标志（`archiveSession(id, { purge: true })`）。** 它能保留一个 Remote 动词和一个权限，但让可逆与不可逆操作共享同一请求形状、同一 Remote 码与同一客户端回调签名；调用方选项写错就会静默销毁转录。分离的动词让破坏性选择在每一层都显式，而让这对操作安全的是 UI 的确认，不是选项名。

**在 Service Definition 上声明抽象 `remove`。** 抽象性是提供方义务的诚实信号，但其他包里有五个测试替身继承该服务以替代后端；把该成员改为抽象会把能力缺口变成本次改动本不触及的包中的编译中断，而静默继承的空操作更糟。以 `SessionRemoveUnsupportedError` 拒绝的具体默认实现让缺口在运行时、在接缝自己的错误词汇中可见。

**在客户端里列举、选中并逐个删除世代。** 选择规则（最高的规范世代）属于后端，扁平文件拼写、临时链接与未来的附带产物都属于后端私有。复现它们的消费方会在布局变化的瞬间漂移，并且还得处理无法从中选择世代的损坏头部。

**像归档那样异步停止（`stopActivity` 先写后停）。** 归档可以先写，因为归档集合本身就是拦住后续唤醒的闸门。删除没有这样的闸门：日志已消失，停止所引发的唤醒会重新实体化它。因此移除在删除之前等待停止请求被**发出**——而不是等工作收敛；这个顺序就是全部保证。

**像 `archiveSession` 一样拒绝未知 id。** 与兄弟动词对称读起来漂亮，但把语义弄反了：向集合添加未知 id 会创造一个指称，而移除未知 id 完成了调用方的请求。拒绝会让双击变成错误，并迫使每个面去特判一个它无法观察的竞争。

**最后一个会话离开时删除项目目录。** 看起来整洁，但该目录派生自一个与其他会话、无主产物以及用户自己的文件共享的 cwd；项目目录不属于存储。只删除会话自己的目录。

## Consequences

被删除的对话无法由任何面恢复：没有撤销、没有归档副本、也没有可重新打开的日志，这正是该动作位于确认之后并被标记为破坏性的原因。Remote 码 `workspace/delete-incomplete` 是用户自己无法修复的结果；它报告对话已消失、只剩注册表清理在等待，并由启动重新索引完成。移除会删除一个会话的所有世代，因此为迁移保留的历史格式世代也随之消失——这可以接受，因为这正是会话停止存在的要点，而替代方案（只删除选中的世代）会让会话通过其余产物继续被列出。

删除不关闭活动句柄。会话被删除后仍追加的写句柄会重新实体化产物；注册表的顺序安排让这条路径在产品中不可达，接缝的 JSDoc 为其他调用方声明了这一义务。冷读句柄持有期间会话被删除时，它从内存读取直到关闭，这属于既有的句柄契约，而不是新的失败模式。

权限模型跟随动词：授予 `workspace/archiveSession` 的组合并不会因此授予 `workspace/deleteSession`，端点不被允许时侧栏隐藏该动作。实时共享端点表将其归类为 `owner-only`，因此查看者看不到该行。

## Testing

`packages/session/session-persistence/tests/remove.spec.ts` 固定默认拒绝与工作开始前的取消。`packages/session/session-persistence-jsonl/tests/remove.spec.ts` 证明一次移除不会在项目目录下留下任何东西——全部世代、一个附带产物以及旧版扁平文件拼写——并证明未知 id 不写入任何东西、未实体化的会话不再被列出、损坏头部仍可删除、文件系统拒绝会让会话保持列出且可安全重试、以及记忆化的解析之后无法作答。`packages/workspace/workspace/tests/workspace.spec.ts` 覆盖账目与集合剪除、未知 id 空操作、运行中工作拒绝、先停后删顺序、后端失败回滚，以及已提交删除但剪除失败时的 `AggregateError`。API 套件覆盖两个 Remote 码与客户端模型对 `stopActivity` 的忠实转发；客户端套件覆盖菜单项（标签、危险标记、垃圾桶字形、权限）、对话框的取消与确认分离，以及列表刷新。
